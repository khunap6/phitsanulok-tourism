# คู่มือติดป้ายรีวิว (สำหรับผู้ตรวจ)

สร้างอัตโนมัติจาก shared/sentiment_labels.json — ห้ามแก้ไฟล์นี้ตรง ๆ
แก้ที่ไฟล์ต้นทางแล้วรัน: uv run python nlp/train/evaluate.py --guideline

## วิธีกรอก

1. เปิด human_eval_300_blank.csv ด้วย Excel หรือ Google Sheets
2. อ่านเฉพาะคอลัมน์ `ข้อความรีวิว` — ห้ามเปิดไฟล์ _system_answer.csv
   เพราะถ้าเห็นคำตอบของระบบก่อน ผลเทียบจะใช้อ้างอิงไม่ได้
3. กรอก `อารมณ์(คนกรอก)` ด้วย positive / neutral / negative
4. กรอก `หมวด(คนกรอก)` ด้วยชื่อหมวดจากรายการท้ายไฟล์นี้
5. ไม่แน่ใจจริง ๆ ให้เว้นว่าง ดีกว่าเดา (ช่องว่างถูกข้าม ไม่นับผิด)
6. กรอกเสร็จแล้วรัน:
   `uv run python nlp/train/evaluate.py --score reports/evaluation/human_eval_300_blank.csv`

## หลักการเดียวที่ใช้ตัดสินอารมณ์

ดูว่า **ผู้รีวิวแสดงความไม่พอใจหรือไม่** ไม่ใช่ดูรูปประโยคหรือคำที่ใช้
คำว่า 'ควร' หรือ 'ปรับปรุง' ไม่ได้แปลว่า negative เสมอไป

## นิยามของอารมณ์ 3 แบบ

- "positive" (คำชม): ผู้รีวิวพอใจ และไม่ได้แสดงความไม่พอใจต่อสิ่งใดอย่างมีนัยสำคัญ
    • ชมตรง ๆ เช่น อร่อย บริการดี บรรยากาศดี
    • แนะนำให้คนอื่นมาใช้บริการ — นับเป็นคำชม ไม่ใช่ข้อเสนอแนะต่อร้าน
    • ชมเป็นหลัก มีติเล็กน้อยแบบผ่าน ๆ ที่ไม่ใช่ประเด็นของรีวิว
    • บอกว่าจะกลับมาอีก / ประทับใจ / คุ้มค่า
- "neutral" (กลางๆ): ไม่ได้แสดงทั้งความพอใจและความไม่พอใจอย่างชัดเจน หรือแสดงทั้งสองอย่างในน้ำหนักพอกัน
    • เล่าข้อเท็จจริงเฉย ๆ เช่น ราคา เวลาเปิดปิด เมนูที่มี
    • เสนอให้เพิ่มหรือปรับ โดยไม่ได้บอกว่าของเดิมแย่ — 'อยากให้มี X' ที่ไม่มีการติ
    • ชมกับติน้ำหนักพอกัน ตัดสินไม่ได้ว่าด้านไหนเด่นกว่า
    • ถามคำถาม หรือพูดถึงเรื่องที่ไม่เกี่ยวกับคุณภาพบริการ
- "negative" (คำบ่น): ผู้รีวิวแสดงความไม่พอใจ ไม่ว่าจะพูดสุภาพหรือรุนแรงแค่ไหน
    • ติ ตำหนิ บ่น ผิดหวัง ไม่ประทับใจ
    • บอกให้ร้านแก้ไขโดยมีการติอยู่ในนั้น — 'ต้องปรับปรุงเรื่อง X'
    • ติเป็นหลัก แม้จะมีคำชมประกอบอยู่ด้วย
    • บอกว่าไม่คุ้ม / ไม่กลับมาอีก / ไม่แนะนำ

ลำดับการตัดสิน:
  1. มีการติหรือแสดงความไม่พอใจไหม — ถ้ามี ไม่ว่าสุภาพแค่ไหน = negative
  2. ถ้าไม่มีการติ แต่มีการชม = positive
  3. ถ้าไม่มีทั้งติและชม หรือมีน้ำหนักพอกัน = neutral
  4. 'แนะนำให้ลอง' ที่พูดกับคนอื่น = positive (เป็นคำชม)
  5. 'ควรปรับปรุง' ที่พูดกับร้านพร้อมการติ = negative
  6. 'อยากให้มี' ที่ไม่ได้ติของเดิม = neutral
  7. ตัดสินจากข้อความที่เขียน ไม่ใช่จากจำนวนดาว
  8. อ่านไม่เข้าใจ หรือเป็นภาษาที่ไม่เข้าใจ = เว้นว่าง ไม่เดา

## หมวดหมู่ที่ใช้ได้ (12 หมวด)

1. การบริการและเจ้าหน้าที่
2. การเดินทางและที่จอดรถ
3. ข้อมูลและป้ายบอกทาง
4. ความคิดเห็นทั่วไป (ไม่ระบุปัญหา)
5. ความปลอดภัย
6. ความสะอาดและสิ่งแวดล้อม
7. ความแออัดและการจัดการ
8. บรรยากาศและการตกแต่งร้าน
9. รสชาติและคุณภาพอาหาร/เครื่องดื่ม
10. ราคาและความคุ้มค่า
11. สิ่งอำนวยความสะดวก
12. อื่นๆ

## เลือกหมวดยังไงเมื่อรีวิวพูดถึงหลายเรื่อง

โมเดลเลือกได้หมวดเดียวต่อรีวิว (single-label, softmax 12 คลาส)
และ DB เก็บได้ช่องเดียว (analyzed_reviews.pain_point_category)
ดังนั้นเวลารีวิวพูดถึงหลายเรื่อง ต้องเลือก 'เรื่องหลัก' เรื่องเดียว

1. ถ้ามีการติ -> เลือกหมวดของ 'สิ่งที่ถูกติ' ไม่ใช่สิ่งที่ชม
   เพราะระบบนี้ทำขึ้นเพื่อหา pain point คำชมที่พ่วงมาไม่ใช่ประเด็น
2. ถ้าติหลายเรื่อง -> เลือกเรื่องที่เป็นประเด็นหลักของรีวิว
   ดูว่าผู้รีวิวให้พื้นที่กับเรื่องไหนมากที่สุด หรือใช้คำรุนแรงกับเรื่องไหน
3. ถ้าชมเรื่องเดียวชัดเจน -> หมวดของเรื่องนั้น
4. ถ้าชมหลายเรื่องน้ำหนักพอกัน -> หมวดที่เด่นที่สุด
   ถ้าเด่นเท่ากันจนเลือกไม่ได้ -> 'ความคิดเห็นทั่วไป (ไม่ระบุปัญหา)'
5. ไม่เกี่ยวกับคุณภาพบริการเลย -> 'อื่นๆ'

### โมเดลตัดสินยังไงจริง ๆ (วัดแล้ว)

**มีติปนชม**
- "อาหารอร่อยแต่ที่จอดรถน้อย" -> การเดินทางและที่จอดรถ (95.6%)  
  เลือกสิ่งที่ถูกติ มองข้ามคำชมทั้งหมด = ตรงกับกฎ 1
- "อาหารอร่อยบรรยากาศดีแต่ที่จอดรถน้อย" -> การเดินทางและที่จอดรถ (93.9%)  
  ชม 2 เรื่องก็ยังแพ้การติ 1 เรื่อง

**ติหลายเรื่อง**
- "ที่จอดรถน้อยแล้วห้องน้ำสกปรก" -> ความสะอาดและสิ่งแวดล้อม (94.5%)  
  เลือกเรื่องที่คำรุนแรงกว่า ที่จอดรถเหลือ 1.1% = ปัญหาหนึ่งหายไป

**ชมเรื่องเดียว**
- "พนักงานบริการดีมาก" -> การบริการและเจ้าหน้าที่ (98.9%)
- "ราคาถูกคุ้มมาก" -> ราคาและความคุ้มค่า (97.3%)
- "บรรยากาศดีมาก" -> บรรยากาศและการตกแต่งร้าน (90.9%)

**ชมหลายเรื่อง**
- "บรรยากาศดีอาหารอร่อย" -> ความคิดเห็นทั่วไป (ไม่ระบุปัญหา) (61.1%)  
  อันดับ 2 บรรยากาศ 31.4% อันดับ 3 รสชาติ 4.8% — ไม่มีหมวดใดเด่นพอ
- "อาหารอร่อยบรรยากาศดี" -> ความคิดเห็นทั่วไป (ไม่ระบุปัญหา) (75.0%)  
  สลับลำดับคำแล้วคำตอบไม่เปลี่ยน แต่ความมั่นใจขยับ

### ข้อจำกัดของการเก็บหมวดเดียว

คำบ่น 2,994 จาก 6,635 รายการ = 45.1% มีคำบ่งชี้ของ 2 หมวดขึ้นไปในข้อความ
แต่ระบบเก็บได้หมวดเดียว ปัญหาที่เหลือจึงไม่ถูกนับในสถิติหมวด

⚠️ 45.1% เป็นขอบบน ไม่ใช่จำนวนจริงของ 'รีวิวที่บ่น 2 ปัญหา'
   นับจากการมีคำบ่งชี้ (regex) ซึ่งคำอาจโผล่มาโดยไม่ได้ถูกบ่นถึง
   เช่น 'อาหารอร่อยแต่บริการแย่' มีคำบ่งชี้ 2 หมวด แต่บ่นแค่เรื่องบริการ

ผลต่อการตีความ: อันดับหมวดปัญหาอ่านได้ว่า 'ปัญหาหลักที่ถูกพูดถึง'
ไม่ใช่ 'จำนวนครั้งที่ปัญหานั้นถูกพูดถึงทั้งหมด' ซึ่งจะต่ำกว่าความจริง
ถ้าจะแก้ต้องเปลี่ยนเป็น multi-label (BCEWithLogitsLoss) + ตารางลูก
ซึ่งต้องติดป้ายชุดเทรนใหม่ทั้งหมด จึงเกินขอบเขตงานนี้

คำชมที่แตะหลายหมวด 19.2% ถูกจัดเป็น 'ความคิดเห็นทั่วไป (ไม่ระบุปัญหา)'
ซึ่งอยู่ใน NON_PROBLEM_CATEGORIES จึงหลุดจากทั้งโหมดคำบ่นและโหมดคำชม
เห็นได้แค่ในโหมด 'ทุกรีวิว' เท่านั้น
