# งาน: ปรับระบบวิเคราะห์รีวิวเป็น Multi-Aspect + Multi-Label Sentiment

## บริบท
โปรเจกต์นี้เก็บรีวิวสถานที่ท่องเที่ยว/ร้านอาหารในพิษณุโลก แล้ววิเคราะห์อารมณ์และหมวดหมู่ เพื่อใช้ในวิทยานิพนธ์และแสดงผลบน dashboard
ตอนนี้ระบบใช้แบบ "1 รีวิว = 1 อารมณ์ + 1 หมวด" ซึ่งเสียข้อมูล เพราะ 63% ของรีวิวพูดถึงหลายเรื่อง
ต้องการเปลี่ยนเป็น "1 รีวิว = อารมณ์รวม 1 ป้าย + หลายหมวด และแต่ละหมวดมีอารมณ์ของตัวเอง"
ตัวอย่าง: "อาหารสดอร่อย แต่รออาหารนาน" → overall: negative, หมวดหลัก 4 / หมวด: (1 อาหาร, positive), (4 บริการ, negative)

## ไฟล์อ้างอิง (อยู่ใน `data/labeling/`)
- `labeling_guide.md` — นิยามป้าย กติกา และหมวดทั้งหมด **อ่านไฟล์นี้ก่อนเริ่มงาน และยึดเป็นมาตรฐานเดียว**
- `categories.csv` — 11 หมวดใหม่ พร้อม mapping จากหมวดเดิม 12 หมวด (เดิม 10→7, เดิม 11→9, เดิม 12 แยกเป็น 10 กับ 11)
- `reviews_labeled.csv` — 300 รีวิวที่ติดป้ายแล้ว ระดับรีวิว (review_id, text, overall_sentiment, primary_category, all_aspects, needs_review)
- `review_aspects.csv` — 571 แถว ระดับหมวด (review_id, category_id, category_name, aspect_sentiment, is_primary)
- ป้ายชุดนี้ใช้เป็น gold set / test set ได้ ห้ามแก้ค่าป้ายในไฟล์เหล่านี้

## ขั้นตอนการทำงาน (ต้องทำตามลำดับ)
1. อ่าน `labeling_guide.md` แล้วสำรวจโค้ดใน `nlp/`, `models/`, `db/`, `api/`, `frontend/`, `scripts/`, `shared/` สรุปให้ผมว่าตอนนี้อารมณ์/หมวดถูกกำหนด เก็บ คำนวณ และแสดงผลที่ไหนบ้าง (ระบุไฟล์และฟังก์ชัน)
2. เสนอแผนการแก้ไขเป็นข้อๆ ว่าไฟล์ไหนแก้อะไร schema เปลี่ยนอย่างไร และข้อมูลเดิมจะ migrate อย่างไร แล้ว **หยุดรอผมอนุมัติก่อนแก้ไฟล์ใดๆ**
3. ก่อนแก้ schema หรือ migrate ข้อมูล ให้สำรองฐานข้อมูลและไฟล์ที่จะแก้ไว้ใน `backup/` พร้อมวันที่
4. ทำทีละส่วนตามแผน และสรุปให้ผมดูหลังจบแต่ละส่วน

## สิ่งที่ต้องเปลี่ยน

### 1) หมวดหมู่
- เปลี่ยนจาก 12 หมวดเป็น 11 หมวดตาม `categories.csv` เก็บรายชื่อหมวดไว้ที่เดียว (เช่น config หรือตารางใน db) แล้วให้ทุกส่วนอ่านจากที่นั้น ห้าม hard-code ซ้ำหลายที่
- ข้อมูลเดิมที่ติดหมวดแบบเก่าไว้ ให้ map ตาม `old_category_ids` ถ้าเป็นหมวดเดิม 12 ซึ่งแยกได้สองทาง ให้ตั้งเป็น 10 ไว้ก่อน แล้ว mark ว่าต้องตรวจ

### 2) โครงสร้างข้อมูล
- ตารางระดับรีวิว เพิ่มหรือปรับเป็น: `overall_sentiment`, `primary_category_id`, `needs_review`
- ตารางใหม่ระดับหมวด: `review_id, category_id, aspect_sentiment, is_primary` (1 แถวต่อ 1 หมวดของรีวิว, primary key = review_id + category_id)
- ค่า sentiment มีแค่ `positive | neutral | negative`
- import ไฟล์ 300 รีวิวข้างต้นเข้าระบบ โดยแยกให้รู้ว่าเป็นป้ายจากคน (gold) ไม่ใช่ป้ายจากโมเดล เช่นคอลัมน์ `label_source = gold | model`

### 3) โมเดล / NLP (ถ้ามีใน `nlp/` หรือ `models/`)
- ทำเป็น 2 ขั้น: (ก) จำแนกหมวดแบบ multi-label ว่ารีวิวพูดถึงหมวดไหนบ้าง (ข) ทำนายอารมณ์ทีละหมวดที่พบ แล้ว (ค) ทำนายอารมณ์รวม
- ประเมินผลด้วย 300 รีวิวข้างต้น: หมวด = micro/macro-F1 แบบ multi-label, อารมณ์รายหมวดและอารมณ์รวม = macro-F1 และ confusion matrix **ห้ามรายงานแค่ accuracy** เพราะข้อมูลเป็น positive ~88%
- บันทึกผลประเมินไว้ใน `reports/`

### 4) Dashboard
- **ตัวเลขภาพรวม** (จำนวนรีวิว, % positive/neutral/negative) ใช้ `overall_sentiment` รวมได้ 100%
- **กราฟรายหมวด** ใช้กราฟแท่งแบบ stacked 👍/😐/👎 จาก `aspect_sentiment` แต่ละแท่ง = "จำนวนรีวิวที่พูดถึงหมวดนี้" และ % คิดจากจำนวนรีวิวทั้งหมด **ห้ามใช้กราฟวงกลมและห้ามคิด % จากผลรวมทุกหมวด**
- ใต้กราฟรายหมวดใส่ข้อความ: "1 รีวิวอาจพูดถึงได้หลายหมวด ตัวเลขแต่ละหมวดจึงรวมกันได้เกินจำนวนรีวิวทั้งหมด"
- แสดงทั้ง "จำนวนรีวิว" และ "จำนวนการกล่าวถึง (mentions)" โดยติดป้ายให้ชัดว่าเป็นคนละหน่วย
- กราฟที่ต้องรวมได้ 100% ตามหมวด ให้ใช้ `primary_category_id`
- หมวดที่มีน้อยกว่า 10 รีวิวในช่วงข้อมูลที่เลือก ให้แสดงผลได้ แต่ติดป้าย "ข้อมูลน้อย" ตั้งค่าเกณฑ์นี้ไว้ใน config
- คลิกที่แท่ง (หมวด + อารมณ์) แล้วกรองแสดงเฉพาะรีวิวนั้นได้
- ถ้า dashboard แยกตามสถานที่ ให้แต่ละสถานที่มีสรุปรายหมวดแบบเดียวกัน

### 5) API
- ปรับ endpoint ให้ส่งทั้งข้อมูลระดับรีวิวและระดับหมวด และมี endpoint สรุปรายหมวด (category_id, n_reviews, n_positive, n_neutral, n_negative, low_data)

## ข้อห้าม
- ห้ามลบข้อมูลดิบหรือผลการ scrape เดิม
- ห้ามแก้ scraper ถ้าไม่จำเป็นต่องานนี้
- ห้ามแก้ป้ายใน gold set
- ถ้าเจอจุดที่ต้องตัดสินใจเรื่องนิยามหรือหมวด ให้ถามผมก่อน อย่าตัดสินใจเอง
